# Scuttle - Privacy-Preserving DeFi Platform

## Overview
Full-stack decentralized application built with Zama's fhEVM v0.9 for Sepolia testnet, featuring:
1. **Token Creation & Presale** - Create ERC20 tokens with encrypted supply and run privacy-preserving presales
2. **NFT Marketplace** - Mint, trade, and auction NFTs with encrypted rarity and attributes (Magic Eden/OpenSea inspired)

## Technology Stack
- **Smart Contracts:** Solidity 0.8.24, Zama fhEVM v0.9, Hardhat
- **Frontend:** React, TypeScript, Vite, TailwindCSS, shadcn/ui
- **Backend:** Express.js, Node.js
- **Database:** PostgreSQL (via Replit)
- **Blockchain:** Sepolia Testnet
- **Encryption:** fhEVM (euint128 for all encrypted values)

- **ConfidentialERC721.sol**
  - OpenZeppelin ERC721 + ERC721Royalty + ReentrancyGuard
  - Three mint functions: basic, with encrypted rarity, with encrypted attributes
  - Encrypted metadata using euint128 (rarity, attributes)
  - Decryption request system via Zama Gateway

- **ConfidentialMarketplace.sol**
  - Full NFT escrow mechanism
  - Listings, offers, and auctions
  - Centralized payout system (_calculatePayout + _executePayout)
  - ReentrancyGuard on all state-changing functions
  - Safe ETH transfers with validation
  - EIP-2981 royalty integration
  - Platform fee system (configurable basis points)

**Security Features:**
- ✅ Reentrancy protection (OpenZeppelin ReentrancyGuard)
- ✅ Safe ETH transfers using .call{value}()
- ✅ Validated payout system prevents fund trapping
- ✅ Escrow tracking prevents double-listing
- ✅ Royalty + fee capping prevents underflow
- ✅ Balance conservation with assert()

### Latest Updates (November 14, 2025) - Production Ready ✅

#### fhEVM Initialization & WASM Loading Fixed ✅ (November 14, 2025)

**Problem 1: Configuration Error**
Users experienced "Failed to initialize fhEVM instance" error when minting NFTs with encrypted rarity.

**Root Cause:** Missing required `kmsContractAddress` parameter in fhevmjs v0.6.2 configuration.

**Solution Applied:**
- Updated `client/src/lib/fhevm.ts` with correct configuration:
  ```typescript
  {
    // REQUIRED parameters
    aclContractAddress: '0x687820221192C5B662b25367F70076A37bc79b6c',
    kmsContractAddress: '0x1364cBBf2cDF5032C47d8226a6f6FBD2AFCDacAC',
    
    // OPTIONAL parameters
    chainId: 11155111,
    networkUrl: 'https://eth-sepolia.public.blastapi.io',
    gatewayUrl: 'https://gateway.sepolia.zama.ai/',
  }
  ```
- Changed `aclAddress` → `aclContractAddress` (correct property name per fhevmjs API)

**Problem 2: WASM Loading Error**
After config fix, new error appeared: `WebAssembly.instantiate(): expected magic word 00 61 73 6d, found 3c 21 44 4f @+0`

**Root Cause:** 
- Vite dev server returned HTML 404 page instead of WASM binary files
- fhevmjs couldn't find `tfhe_bg.wasm` and `kms_lib_bg.wasm` files
- Bytes `3c 21 44 4f` = ASCII `<!DO` (HTML DOCTYPE)

**Solution Applied:**
1. **Copied WASM files to public folder:**
   ```bash
   cp node_modules/fhevmjs/lib/tfhe_bg.wasm client/public/ (2.9MB)
   cp node_modules/fhevmjs/lib/kms_lib_bg.wasm client/public/ (515KB)
   ```

2. **Updated initFhevm to use public folder paths:**
   ```typescript
   await initFhevm({
     tfheParams: '/tfhe_bg.wasm',
     kmsParams: '/kms_lib_bg.wasm',
   });
   ```

**Problem 3: Wrong Gateway URL**
After WASM fix, new error: `Impossible to fetch public key: wrong gateway url`

**Root Cause:**
- Incorrect gateway URL: `https://gateway.sepolia.zama.ai/`
- Missing network provider in createInstance() configuration

**Solution Applied:**
1. **Updated gateway URL to official Zama relayer:**
   ```
   https://relayer.testnet.zama.cloud
   ```

2. **Added network provider to configuration (attempted with BrowserProvider.provider):**
   ```typescript
   network: (provider as any).provider, // ❌ Returns empty object {}
   ```

**Problem 4: Invalid EIP-1193 Provider**
After gateway URL fix, new error: `invalid EIP-1193 provider (argument="ethereum", value={}, code=INVALID_ARGUMENT)`

**Root Cause:**
- BrowserProvider doesn't expose `.provider` property that returns the original EIP-1193 provider
- `(provider as any).provider` returned empty object `{}` instead of valid provider
- fhevmjs requires the raw EIP-1193 provider from wallet (window.ethereum)

**Solution Applied:**
**Use window.ethereum directly instead of extracting from BrowserProvider:**
```typescript
const config = {
  aclContractAddress: '0x687820221192C5B662b25367F70076A37bc79b6c',
  kmsContractAddress: '0x1364cBBf2cDF5032C47d8226a6f6FBD2AFCDacAC',
  network: window.ethereum, // ✅ Direct access to EIP-1193 provider
  chainId: 11155111,
  gatewayUrl: 'https://relayer.testnet.zama.cloud',
};
```

**Impact:**
- ✅ WASM files served correctly with `Content-Type: application/wasm`
- ✅ Valid EIP-1193 provider passed to fhEVM
- ✅ fhEVM instance initializes successfully on Sepolia
- ✅ Console logs show all 4 initialization steps
- ✅ Encrypted NFT minting ready for production
- ✅ No more "magic word", "wrong gateway", or "invalid provider" errors

**Files Modified:**
- `client/src/lib/fhevm.ts` - Configuration, WASM paths, and EIP-1193 provider
- `client/public/tfhe_bg.wasm` - TFHE cryptographic operations (new)
- `client/public/kms_lib_bg.wasm` - KMS library (new)
